# WowRunner Agent Maintenance Guide

## Project scope

WowRunner is the internal project name for the Windows-only .NET 8 WinForms product **暴雪战网启动配置管理器**. It launches a configured executable under a selected Windows user.

Target runtime and architecture:

- Target framework: `net8.0-windows`
- Runtime identifier: `win-x64`
- Output: self-contained single-file `WowRunner.exe`
- UI: hand-written WinForms controls in `MainForm.cs`; there is no `.Designer.cs` file
- Installer: self-contained WinForms setup EXE generated by `installer/build-installer.ps1`
- 应用输出类型是 `WinExe`，避免通过快捷方式启动时出现控制台窗口。
- `Assets/wowrunner.ico` 是应用与安装器图标；profile 快捷方式优先使用目标 EXE 的第一个图标，找不到目标时回退到 WowRunner 图标。

## Source map

- `Program.cs`: GUI/CLI startup dispatch and command handlers.
- `MainForm.cs`: profile editor, credential save, direct launch, shortcut creation, and account initialization UI.
- `PasswordPromptForm.cs`: password dialog used when the elevated identity cannot read the original user's Credential Manager entry.
- `Models/RunnerConfiguration.cs`: `RunnerConfiguration` and `LaunchProfile` JSON models.
- `Services/ConfigurationStore.cs`: reads, writes, validates, and resolves profile configuration.
- `Services/CredentialStore.cs`: Windows Credential Manager storage. Passwords must stay out of JSON, logs, command lines, and error messages.
- `Services/WindowsProcessLauncher.cs`: `CreateProcessWithLogonW` implementation. It uses `LOGON_WITH_PROFILE` and resolves relative paths from the executable directory.
- `Services/WindowsAccountInitializer.cs`: local account creation through `NetUserAdd`; only local users are supported.
- `Services/Elevation.cs`: UAC restart helper for CLI and configured administrator launches.
- `appsettings.json`: runtime configuration next to the executable.
- `appsettings.example.json`: editable configuration reference.
- `installer/build-installer.ps1`: publishes the application, embeds the published files into a WinForms setup EXE, and builds `installer/dist/WowRunner-Setup.exe`.
- `installer/WowRunner.Setup.csproj`: visible setup application project.

## Configuration contract

Each `Profiles` item maps one profile name to one Windows identity and one launch definition:

```json
{
  "Name": "wow",
  "WindowsUser": ".\\wow",
  "ExecutablePath": "C:/Program Files (x86)/Battle.net/Battle.net Launcher.exe",
  "WorkingDirectory": "C:/Program Files (x86)/Battle.net",
  "Arguments": ["--setregion=US", "--setlanguage=enCN"]
}
```

- `WindowsUser` 在配置器中只输入裸用户名，例如 `wow1`、`wow-alt` 或 `wow_test`；仅允许以英文字母开头，后接英文字母、数字、连字符或下划线。保存时底层统一规范化为 `.\wow1`。
- 选择或离开程序路径输入框后，配置器自动把工作目录更新为可执行文件所在目录；用户仍可手动修改工作目录。
- Relative executable and working-directory paths resolve from the directory containing `WowRunner.exe`.
- Profile names must be unique and valid Windows file names because they are used in Credential Manager targets and shortcut names.
- The configuration must retain at least one profile.
- `RequireAdministrator` controls direct/CLI profile launches. Account initialization always requests UAC.

## Credentials and account initialization

- Credential target names are `WowRunner/<profile-name>` in the current Windows user's Credential Manager.
- `credential set <name>` updates a profile password without modifying JSON.
- `credential clear <name>` 也接受已从配置中删除的旧名称，用于清理遗留凭据。
- 删除 profile 时，界面会询问是否同时删除本地 Windows 用户及其用户目录；只删除配置立即执行，同时删除账号必须完成十秒倒计时确认并通过 UAC。
- A UAC elevation using a different administrator identity cannot read the original user's Credential Manager entry. In that case `account init <name>` opens `PasswordPromptForm` in the elevated process and receives the password interactively.
- `WindowsAccountInitializer` creates a local account only. Do not extend it to domain accounts without a separate identity/permission design.
- Never add password values to configuration, command-line arguments, shortcut arguments, logs, exception text, or source control.

## User-facing commands

```text
WowRunner.exe
WowRunner.exe run <profile>
WowRunner.exe list
WowRunner.exe credential set <profile>
WowRunner.exe credential clear <profile>
WowRunner.exe account init <profile>
WowRunner.exe account delete <profile>
WowRunner.exe config
WowRunner.exe help
```

No arguments opens the WinForms configuration manager. Shortcuts call `WowRunner.exe run <profile>`.

## Build and package verification

Run from `D:\code\wow_runner`:

```text
dotnet build --configuration Debug
dotnet publish --configuration Release --runtime win-x64 --self-contained true --output publish
pwsh.exe -NoLogo -File installer/build-installer.ps1
```

Expected artifacts:

- `publish/WowRunner.exe`
- `installer/dist/WowRunner-Setup.exe`

After source changes, run the smallest affected build first, then publish the final EXE and run:

```text
WowRunner.exe help
WowRunner.exe list
```

Do not launch Battle.net or create a Windows account as an automated build check. Those operations have real side effects and require explicit user-controlled credentials.

## Operational caveats

- Battle.net may enforce a single-instance or agent process. Close existing Battle.net/Agent/WoW processes before testing a different Windows profile.
- Switching Windows users isolates `%APPDATA%`, `%LOCALAPPDATA%`, and `HKCU`, but WoW's installation-directory `WTF`, `Interface`, and `Cache` folders can remain shared. Separate those directories or installations when full WoW profile isolation is required.
- The installer is per-user and installs under `%LOCALAPPDATA%`; account initialization performs its own UAC elevation.
- `installer/staging/`, `installer/dist/`, `publish/`, `bin/`, `obj/`, and the generated `.sed` file are build artifacts and stay ignored.

## Change discipline

When changing launch behavior, preserve all of these contracts together: profile selection, credential lookup, `LOGON_WITH_PROFILE`, argument tokenization, working-directory resolution, administrator behavior, shortcut arguments, and error handling. Verify both GUI launch and CLI/shortcut launch paths after changes.
